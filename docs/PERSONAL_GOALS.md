# 개인 목표 보드

첫 화면은 개인 목표 보드이며 `#/goals`로 접근합니다. 운동 타이머는 독립 메뉴 `#/timer`로 분리했으며, 기존 봉사 기록은 `#calendar`에 유지합니다. 성경 시간순 읽기는 메뉴에서 제외했으며 관련 데이터, SQL, 저장 모듈은 보존했습니다.

- 목표 이름과 수행일 수(1~365)를 설정합니다. 왼쪽 START와 오른쪽 GOAL 사이에 수행일 수만큼 칸이 생깁니다. 한 줄로 이어진 풍경과 길 위에서 깃발 캐릭터가 좌우로 움직이며, 모바일에서도 전체 경로가 보입니다.
- 날짜마다 ＋(1), 스테이(0), －(-1) 중 하나를 저장합니다. 오늘과 과거 날짜를 평가할 수 있습니다.
- 같은 날짜를 다시 평가하면 기존 값을 대체합니다. 날짜 오름차순으로 전체 기록을 다시 계산하며, 매 단계 위치를 0~목표 칸 사이로 제한합니다.
- － 평가가 있는 날짜 수를 누적 실패로 표시합니다. 3일 이상이면 강조된 시각 알림과 단호한 격려를 표시합니다. 평가를 수정하면 누적 실패도 다시 계산합니다.
- 목표 설정을 변경해도 평가 기록은 보존합니다. 별도 초기화 기능은 없습니다.
- 휴식 타이머는 90초·2분·3분, 일시정지·계속·초기화를 지원합니다. 절대 종료 시각으로 남은 시간을 계산하여 백그라운드 지연을 보정합니다. 종료 시각을 브라우저에 저장하므로 페이지 이동·새로고침 후에도 유지됩니다. 완료 시 짧은 4음 차임과 화면 안내를 제공하며 알림을 허용한 브라우저에서는 시스템 알림도 표시합니다. 모바일에서 브라우저 실행이 중단되거나 앱이 종료되면 정시 알람은 보장하지 않으며, 복귀 시 만료를 확인합니다. 서버 푸시 예약은 구현하지 않았습니다.

## 저장과 보존

목표는 **현재 브라우저의 localStorage**에만 저장하며 기기 간 동기화하지 않습니다. 기본 키는 `chagok.goals.v1`이고, 온라인 봉사 계정으로 로그인한 경우 `.사용자UUID`를 붙여 브라우저 내 계정별로 분리합니다. 로그인 전 목표와 로그인 후 목표는 서로 별도이며 자동 병합하지 않습니다. 예시 모드에서는 영구 저장하지 않습니다. 브라우저 데이터를 삭제하면 목표 기록도 사라집니다.

기존 봉사 기록 키 `chagok.journal.v1`, Supabase `personal_journals`, 이전 봉사 테이블, 인증 설정과 RLS 정책은 변경하지 않습니다. 새 테이블이나 운영 DB 마이그레이션이 필요하지 않습니다. 목표 저장 시 손상된 기존 데이터와 다른 탭에서 변경된 데이터의 자동 덮어쓰기를 차단합니다.

## 검증

`npm test`, `npm run build`, `CHROMIUM_PATH=/usr/bin/chromium npx playwright test e2e/personal-goals.spec.ts e2e/local.spec.ts e2e/journal.spec.ts e2e/goals.spec.ts e2e/reset.spec.ts`

기존 봉사 테스트는 새 첫 화면 도입에 맞춰 `#calendar`로 진입합니다. 운영 배포는 별도 단계입니다.

캐릭터는 사용자가 제공한 곰 이미지를 바탕으로 배경을 투명화한 웹 이미지입니다. 평가 버튼은 이동 방향에 맞춰 － / 스테이 / ＋ 순서로 배치합니다.

격려 문구 42개를 일상·＋·스테이·－·목표 달성 상황에 맞춰 제공합니다. 날짜와 진행 상황에 따라 문구가 바뀌며, ‘다른 격려 보기’로 넘길 수 있습니다. 식사량 사전 결정, 추가 주문·간식·단 음료 조절, 주말 외식 계획 등 구체적인 식단 실천을 강조합니다. 스테이는 다음 식사에서 바꿀 행동을 정하도록 독려하며, 체중 정체를 칭찬하거나 감량 결과를 보장하지 않습니다.
