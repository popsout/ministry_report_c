# 차곡 개인 목표 관리

## 사용 흐름

첫 화면은 목표 관리입니다. 기존 봉사 기록은 `#calendar` 메뉴에서 그대로 사용합니다. 성경 읽기 메뉴와 진입 화면은 중단했으며, 관련 자료·테이블·권한은 삭제하지 않았습니다.

1. 목표 이름, 수행일 수(1~365칸), 시작일, 실천할 식사 계획을 저장합니다.
2. 하루가 끝나면 평가 날짜를 확인하고 ＋ 업 / 스테이 / － 다운을 누릅니다.
3. 같은 날짜에 다시 누르면 기존 평가를 수정합니다. 과거 평가 수정 시 이후 평가까지 날짜순으로 다시 계산합니다.
4. 휴식 타이머의 1분 30초 / 2분 / 3분을 누르면 즉시 시작합니다. 한 번에 하나만 실행하며, 프리셋을 다시 누르면 해당 시간으로 바뀝니다.

칸은 순전진 횟수입니다. 체중 측정이나 감량 예측 기능이 아닙니다. 미기록일은 실패가 아니며, 각 평가를 순서대로 적용할 때 위치를 0~목표 칸 사이로 제한합니다. 시작점 다운 → 다음 날 업은 1칸입니다. 목표 도착 후 다운을 평가하면 한 칸 뒤로 이동합니다. 날짜는 Asia/Seoul 기준입니다.

## 기존 데이터 보존

- `chagok.journal.v1`, `personal_journals`, `service_entries`, `month_settings`와 기존 인증·RLS 정책을 변경하지 않습니다.
- 목표 데이터는 별도 localStorage 키 `chagok.goals.v1` 또는 Supabase `personal_goals`에 저장합니다.
- 기존 봉사 문서의 `entries/settings` 형식은 확장하지 않습니다.
- 로컬과 온라인 기록을 자동 이전하거나 합치지 않습니다.
- 손상된 목표 데이터는 자동 덮어쓰기하지 않습니다. 저장 실패 시 입력을 유지합니다.
- 계획 조정은 날짜별 평가를 보존합니다. 첫 평가일보다 늦은 시작일로 변경할 수 없습니다.
- 단일 HTML도 새 기능을 포함하며 기존 봉사 기록 키를 그대로 사용합니다. 실행 주소나 파일 위치가 달라지면 브라우저 저장 영역이 달라질 수 있습니다.

## 온라인 저장 준비

운영 DB에 적용한 것으로 간주하지 마세요. 구현 검증에는 모의 API와 격리된 PostgreSQL을 사용했습니다.

기존 Supabase 프로젝트의 SQL Editor에서 `supabase/007_personal_goals.sql`을 별도로 적용합니다. 이 SQL은 목표용 테이블·RLS·충돌 검사·Realtime 등록만 추가합니다. 기존 봉사·성경 SQL을 다시 실행할 필요가 없습니다. 관리자 키나 비밀번호를 코드·채팅에 넣지 않습니다.

웹 빌드에는 기존 공개 연결 설정 `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, `VITE_ENABLE_CLOUD=true`를 사용합니다. 개발 시에는 연결 설정과 `?cloud=1`로 시험할 수 있습니다. 온라인 모드에서 새 테이블을 읽지 못하면 오류를 표시하고 저장을 막으며, 로컬로 자동 전환하지 않습니다. 기존 봉사 화면은 계속 사용할 수 있습니다.

테이블의 계정별 문서에는 목표 설정·날짜별 평가·오늘 닫기 날짜를 저장합니다. 본인 계정만 읽고 수정할 수 있도록 RLS를 적용하고, `revision` 비교로 오래된 변경의 덮어쓰기를 막습니다. Realtime, 화면 복귀, 온라인 복귀, 15초 재조회로 갱신합니다. 오래 열린 계획 편집도 시작 시점의 revision으로 검사합니다.

실제 운영에서는 SQL 적용 후 PC와 휴대폰에서 같은 계정으로 목표를 저장·수정하고 서로 반영되는지 확인해야 합니다. 계정·인증 URL·기존 테이블 권한은 이 작업 때문에 바꿀 필요가 없습니다.

## 알림·타이머

- 연속된 달력 날짜에 다운 3건: 노란 주의. 현재 흐름 판단은 마지막 평가가 오늘 또는 어제인 경우에 합니다. 미기록일은 연속 조건을 끊습니다.
- 최근 평가 7건 중 다운 4건 이상: 주황 주의. 평가 사이의 미기록일은 집계 대상이 아닙니다. 두 조건을 만족하면 주황 하나만 표시합니다.
- 오늘 닫기는 한국 날짜 기준이며 날짜가 바뀌면 조건을 다시 판단합니다. 계획 조정은 실제 목표 설정을 엽니다.
- 조건·격려 문구는 `src/lib/goals.ts`에 분리했습니다.
- 타이머는 종료 시각으로 남은 시간을 계산하고 일시정지 시 잔여 시간을 보관합니다. 같은 탭의 새로고침·메뉴 이동은 sessionStorage로 복원합니다. 다른 탭·다른 기기 간 타이머 공유는 제공하지 않습니다.
- 타이머 종료는 시각 표시입니다. 소리·잠금 화면·백그라운드 푸시 알림은 제공하지 않습니다. 브라우저의 백그라운드 정지 이후 화면에 돌아오면 종료 여부를 맞춥니다.
- `prefers-reduced-motion`에서 이동 전환과 깃발·점프 애니메이션을 생략합니다.

곰 캐릭터는 코드로 만든 SVG 임시 자산입니다. 이전 대화의 이미지나 미커밋 자료를 복구한 것이 아닙니다.

## 검증과 배포 구분

`npm test`는 도메인·타이머·기존 데이터 형식과 로컬 PostgreSQL RLS를 확인합니다. 브라우저 검사는 실제 운영 기록 대신 빈 브라우저와 모의 인증/API를 사용합니다. 새 화면은 `e2e/personal-goals*.spec.ts`, 기존 봉사 화면은 기존 검사 파일에 유지합니다. 기존 봉사 검사 URL은 새 첫 화면에 맞춰 `#calendar`로 지정했습니다.

중단된 성경 읽기 화면 검사는 현재 제품 범위에서 실행하지 않습니다. 기존 파일과 자료는 보존합니다.

배포 전 `npm run build`와 `npm run build:standalone`으로 웹·한 기기용 HTML을 생성합니다. 운영 동기화 검증과 GitHub Pages 배포는 코드 작성·로컬 검사와 별도 단계입니다.
