# 성경 시간순 읽기 — 기존 구조 점검과 시범 설계

작성일: 2026-10-26. 아래는 초기 구조 점검·설계 기록이다. 이후 구현한 요약 화면·권한 SQL·암호화 서가와 소유자의 활성화 절차는 [현재 구현 안내](BIBLE_READING_SETUP.md)를 따른다. 신세계역 본문은 아직 수록하지 않았다.

## 제안하는 범위

기존 봉사 기록장에 **성경 시간순 읽기** 메뉴를 추가한다. 새 기능에만 관리자 제한을 적용하고, 기존 봉사 기록의 계정별 접근 방식은 유지한다.

사용자의 후속 설명에 따라 범위를 **구약 전체의 큰 사건 흐름을 통합한 시간순 요약**으로 수정한다. 앞서 제안한 창조~출애굽 한정안과 단순한 성경책별·시대별 요약은 현재 목표를 대신하지 않는다. 첫 결과물은 전체 본문 수입이 아니라, 중복 사건을 통합하고 시간적 위치가 떨어진 책들을 연결한 읽기 지도다.

핵심 편집 규칙:

- 열왕기와 역대기의 병행 기록은 같은 사건 카드 하나에 연결한다. 예를 들어 솔로몬의 성전 건축·봉헌을 하나의 흐름으로 요약하고 열왕기상 6–8장과 역대기하 3–7장을 관련 본문으로 제공한다. 이 구간 전체가 절 단위로 동일하다는 뜻은 아니며 사건별 대응은 검토 후 나눈다.
- 사무엘·역대기의 병행 기록도 같은 원칙으로 묶는다. 사건 요약은 한 번 제시하고, 각 기록에만 있는 내용은 출처를 붙인 추가 설명으로 구분한다. 서로 다른 관점과 세부사항을 억지로 동일화하거나 본문을 섞어 새 성경 문장을 만들지 않는다.
- 욥기는 독립된 책 순서에 방치하지 않고, 관련 출판물이 제시하는 사건 발생 시기의 근거를 확인해 해당 시대 안에 배치한다. 사건의 시기와 집필 시기는 분리한다. 아직 출처를 검증하지 않았으므로 이 설계에서 특정 연도나 확정 위치를 선언하지 않는다.
- 예언서도 왕국 분열·멸망·유배·귀환이라는 사건 흐름 속에 연결한다. 한 책이 여러 시대에 걸치면 관련 구간을 나눠 연결하고 책 전체를 한 시점에 고정하지 않는다.
- 시편 등은 근거가 확인된 관련 사건·시대에 연결하되, 시기를 알 수 없는 본문은 미상으로 표시한다. 불확실한 배치를 위해 인접 본문의 절대연도까지 추정하지 않는다.
- 첫 화면에는 큰 사건의 연결만 보여준다. 날짜·구간 대응·여러 출처 비교·배치 근거는 펼쳐 보는 상세 정보로 둔다. 큰 흐름을 간소화하더라도 불확실한 배치 표시는 숨기지 않는다.

첫 검토 표는 `시대 / 통합 사건 / 병행 본문들 / 각 기록의 추가 내용 / 관련 예언서·시가서 / 당시 나라·통치자 / 배치 근거 / 불확실성`으로 만든다. 병행 본문을 한 사건에 묶는 관계와, 단순히 같은 시대에 속하는 관계를 데이터와 화면에서 구분한다. 통합표의 대표 사례를 먼저 확인한 뒤 화면으로 옮긴다.

### 당시 나라와 통치자 병기

각 사건 카드의 요약 아래에 `나라 — 당시 통치자`를 표시한다. 사건과 직접 관련된 나라를 우선하며, 주변 강국은 사건의 배경을 설명하는 데 필요할 때 함께 표시한다. 분열 왕국 시대에는 남유다·북이스라엘의 동시대 왕을 나란히 보여 서로 다른 왕국의 기록을 연결할 수 있게 한다.

- 인물의 이름·나라·당시 직함과 통치 기간을 별도 자료로 관리하고 사건에 연결한다. 왕명 표기는 확인한 신세계역 판본에 맞추며 동명이인 왕과 이름의 다른 표기를 구분한다.
- 한 사건 묶음이 여러 왕의 통치에 걸치면 해당 왕들을 순서대로 표시한다. 공동 통치·계승 경계·정확한 재위 기간에 불확실성이 있으면 근거와 함께 표시하고 한 명으로 단정하지 않는다.
- 왕정 이전에는 재판관·지도자 등의 실제 직함을 사용하거나 왕 없음으로 표시한다. 해당 왕국이 이미 멸망한 시점에는 존재하지 않는 왕을 병기하지 않는다. 지방 총독과 제국의 왕도 구분한다.
- 성경에 이름이 없는 파라오는 임의로 특정 역사 인물과 동일시하지 않는다. 통치자를 확인하지 못하면 미상으로 표시한다.
- 예시 화면 구성: `예루살렘 멸망 → 유다: 시드기야 / 바빌론: 느부갓네살 → 통합 사건 요약 → 관련 성경 구간`. 실제 자료 등록 시에는 해당 연결의 성구와 출판물 근거를 대조한다.

화면 흐름은 `시대 → 사건 목록 → 사건 설명·연대 근거 → 관련 본문`이다. 본문은 사이트 안에서 절 단위로 읽으며, 글자 크기 조절·이전/다음 사건·현재 읽는 위치·온라인/저장됨/미저장 표시를 제공한다. PC에는 목록과 본문을 나란히, 휴대폰에는 단계별 화면을 제공한다.

첫 요약 시범에서는 검색 전체 기능, 성경 전체 본문 수입, 출판물 전문 수입, 다른 사용자 초대, 브라우저에서 관리자 권한 부여, 본문 편집기, 기존 봉사 기록의 백업 구조 변경은 포함하지 않는다.

## 기존 코드에서 확인한 사실

| 항목 | 확인 결과와 설계상 의미 |
| --- | --- |
| 화면·호스팅 | React 19 / TypeScript / Vite. GitHub Pages용 정적 빌드. 별도 앱 서버는 없다. `src/App.tsx`, `vite.config.ts`, `scripts/publish-pages.py` |
| 메뉴 | 현재 봉사 기록 단일 화면이며 별도 화면 라우터는 없다. 새 화면은 `#/bible` 같은 해시 경로로 추가하면 Pages 새로고침 404를 피할 수 있다. |
| 인증 | `src/lib/supabase.ts`, `src/lib/cloudJournal.ts`, `src/App.tsx`의 Supabase 이메일·앱 전용 비밀번호 로그인. Google OAuth는 현재 사용하지 않는다. |
| 온라인 봉사 기록 | `personal_journals`의 사용자별 JSON 문서. `supabase/003_personal_journals.sql`은 `auth.uid() = user_id` RLS와 revision 충돌 검사를 사용한다. 성경 본문은 이 문서에 넣지 않는다. |
| 관리자 | 코드와 SQL에 별도 관리자 목록·관리자 RLS는 없다. 파이오니아 `role`은 봉사 신분이며 접근 권한과 무관하다. |
| 오프라인 | 한 기기 모드의 봉사 기록은 localStorage를 사용한다. 앱 셸 저장용 Service Worker, 성경 저장용 IndexedDB, 암호화 저장소는 없다. |
| 보안 정책 | 빌드에 CSP가 있다. 새 Service Worker에 필요한 `worker-src 'self'`와 실제 배포 경로의 scope를 검토해야 한다. |
| 배포 | 코드와 정적 산출물은 공개된다. 원본 PDF·추출 본문·본문 JSON을 소스, `public/`, 번들, `chagok.html`, `dist` 또는 `gh-pages`에 넣어서는 관리자 제한을 달성할 수 없다. |

운영 서버에서 공개 클라이언트 설정으로 수행한 읽기 전용 확인:

- 익명으로 `personal_journals` 조회: HTTP 401 / PostgreSQL 42501. 익명 조회 거부를 확인했다.
- 공개 Auth 설정: `disable_signup=false`, `mailer_autoconfirm=false`. 현재 신규 가입을 허용하며 이메일 확인을 요구한다. 설정은 변경하지 않았다.
- 기존 RLS의 격리된 PostgreSQL 검사는 첫 실행에서 30초 제한을 넘겼고, 재실행에서는 2.7초에 통과했다. 새 관리자 정책은 아직 작성·검증하지 않았다.
- 이 확인은 관리자 계정 인증, 다른 실제 계정과의 RLS 비교, 운영 DB의 전체 권한 감사를 대신하지 않는다. 운영 DB 관리 키나 사용자의 로그인 비밀번호를 사용하지 않았다.

## 서버에서 관리자만 허용하는 방식

기존 Supabase를 그대로 사용한다. 별도 유료 서버를 새로 만들 필요는 없다. GitHub Pages는 공개 화면 파일을 제공하고, **본문과 성경 메타데이터의 실제 접근 판단은 Supabase 서버가 담당**한다. 공개 화면 파일 자체를 관리자만 내려받게 하는 것은 현재 Pages 구성으로 제공되지 않는다.

1. API에 노출하지 않는 `bible_private.bible_admins`에 본인 Supabase 사용자 UUID를 등록한다. 최초 등록·해제는 소유자의 SQL Editor 등 신뢰할 수 있는 관리 경로로만 한다. 이메일 접두어, 첫 가입자, 브라우저 상수, 사용자가 수정할 수 있는 `user_metadata`로 관리자를 정하지 않는다.
2. 관리자 여부를 반환하는 제한된 함수를 둔다. 필요한 경우 `SECURITY DEFINER`를 쓰되 소유자·실행 권한·빈 `search_path`와 명시적 스키마를 고정하고, 전달받은 UUID가 아니라 검증된 요청의 `auth.uid()`를 검사한다. 관리자 목록 조회·수정 권한은 클라이언트에 주지 않는다.
3. 성경 관련 새 테이블에는 RLS를 활성화하고 모든 읽기 경로에 관리자 검사를 적용한다. `anon`은 차단하고 일반 `authenticated` 사용자도 관리자 검사에 실패하면 데이터를 받지 못한다. 본문 수입은 관리 경로로 처리하며 시범 브라우저에는 본문 쓰기 권한을 주지 않는다.
4. 메뉴 노출·화면 진입 검사는 편의를 위한 추가 장치다. 직접 REST 요청, 임의 해시 경로, 수정한 브라우저 코드로 접근해도 서버 정책이 차단해야 한다. 성경 메뉴는 `?preview=1`, `?device`, 기존 단독 HTML에서 우회하여 본문을 제공하지 않는다.
5. 원본 PDF는 시범 서버에 올리지 않는 방식을 우선한다. 보관이 필요하면 별도 비공개 Storage와 관리자 정책을 추가하고 공개 URL을 만들지 않는다. 다운로드 URL을 쓰더라도 짧은 만료만으로 관리자 권한 검사를 대체하지 않는다.

신규 가입 차단은 본인 전용 운영을 위한 별도 선택이다. 가입을 막더라도 관리자 RLS는 필요하다. 새 기능을 구현할 때 본인 사용자 UUID를 소유자가 직접 확인해 등록해야 하며, 비밀번호·세션 토큰·관리 키를 채팅에 보낼 필요는 없다.

## 자료 구조와 연대 편집 원칙

봉사 기록과 분리된 새 테이블/구조를 사용한다.

| 자료 | 필요한 정보 |
| --- | --- |
| 판본 | 언어, 개정판, 인쇄연도, 판권문, 수입 버전, 원본 해시, 이용 조건 확인 상태 |
| 본문 | 판본 ID, 성경책·장·절, 본문, 원본 PDF 페이지, 추출·교정 상태 |
| 시대·사건 | 제목, 읽기 순서, 요약, 관련 본문 구간, 앞뒤 관계 또는 동시기 관계, 관련 나라·통치자 연결 |
| 나라·통치자 | 나라, 왕명·이름의 다른 표기, 직함, 재위 구간과 불확실성, 동시대·공동 통치 관계, 근거 ID |
| 연대·배치 주장 | 출처가 제시한 연도/범위/상대 순서/미상, 불확실성 설명, 대안 배치, 해당 근거 ID |
| 근거 | 출판물 제목·판본·발행일, 항목·쪽·문단, 공식 링크, 검토일, 직접 명시/편집상 추론 구분 |

| 재앙·유월절·출애굽 | 출애굽기 7–13장 |
| 홍해를 건넘 | 출애굽기 14–15장 |

본문 장 순서를 곧 사건의 시간순이라고 취급하지 않는다. 반복 서술, 계보, 회고, 병행 사건은 따로 표시한다. 한 사건에 여러 본문 구간을 연결할 수 있고, 연결된 구간 안의 절 순서는 보존한다. 구간이 겹치는 읽기 목록은 중복 표시 여부를 명시한다.

- 창조 전체와 인간 역사 시작을 같은 연도로 묶지 않는다. 절대연도가 없는 항목에 임의 숫자를 넣지 않는다.
- 구체적 연도는 여호와의 증인 출판물의 근거가 확인된 뒤 입력한다. 표시도 “해당 출판물이 제시하는 연대”와 “그 자료로부터 편집자가 추론한 배치”를 구분한다.
- “기원전 ○년경 / 근거” 또는 “정확한 시기 미상 / 앞뒤 관계의 근거”처럼 설명한다. 정밀도를 소수점 확률로 꾸며내지 않는다.
- 연대, 사건의 선후관계, 본문을 배치한 편집상의 확실성은 각각 따로 관리한다. 날짜가 불확실해도 사건 순서는 자료에서 명시될 수 있다.
- 기원전 날짜는 현대 달력의 JavaScript `Date`로 대충 변환하지 않는다. 기원 구분과 연도/범위/상대 순서 필드를 저장한다.
- 욥기 등 병행 배치가 필요한 본문은 출판물 근거를 확인하기 전에는 시범의 확정 읽기 순서에 삽입하지 않는다.
- 기준 출처 후보는 신세계역의 연대표·부록과 「성경 통찰」의 관련 항목 등이다. 실제 항목·판본·문단을 확인한 후 근거로 채택한다. 출판물 전문을 함께 복제하는 방식은 시범에 포함하지 않는다.

## 오프라인 읽기와 기기 내 보호

서버 인증과 오프라인 잠금은 구분한다. 처음 온라인에서 관리자임을 확인한 뒤 저장한 본문만 오프라인에서 읽는다. 서버의 읽기 허용과 오프라인 복제 허용은 이용 조건에서 각각 검토한다.

### 저장 흐름

1. 최초 접속·관리자 확인은 온라인에서 한다. 사건 화면의 본문을 가져와 표시하고, 오프라인 저장을 사용하도록 한 기기에서는 성공적으로 읽은 본문을 장 단위로 암호화 저장한다. 아직 받지 않은 장은 미저장 상태로 둔다. 시범 범위 전체 저장은 이용 조건 확인 후 제공할 선택 기능이다.
2. Service Worker에는 공개 앱 셸(JS/CSS/기본 화면)만 저장한다. Supabase Auth, REST, Storage 응답과 복호화 본문은 범용 HTTP 캐시/Cache API/정적 프리캐시에 넣지 않는다. 관리자 데이터 요청에는 별도 캐시 방지 설정을 적용한다.
3. 본문과 관련 민감 메타데이터는 계정·판본·콘텐츠 버전별로 IndexedDB에 암호문으로 저장한다. 로그인 세션과 관계없는 별도 기기 잠금으로 여는 개인 서가를 제공한다.
4. 오프라인에서는 저장된 장만 표시한다. 미저장 본문과 공식 웹사이트의 외부 링크는 오프라인에서 열 수 없음을 표시한다. PDF 웹뷰/iframe을 저장하는 방식은 쓰지 않는다.
5. 앱 셸을 저장해야 비행기 모드에서도 사이트를 다시 열 수 있다. 기존 `chagok.html`만으로 온라인 관리자 콘텐츠의 보호·오프라인 읽기를 대신하지 않는다.

### 권장 보호 수준

Web Crypto의 AES-GCM으로 장별 본문을 암호화하고 매번 새 IV를 사용한다. 키는 별도의 기기 잠금 암호에서 충분한 비용의 PBKDF2-SHA-256과 임의 salt로 유도한 키로 보호한다. 실제 반복 수는 저성능 휴대폰에서 측정해 정하고, 알고리즘·salt·반복 수·버전을 저장한다. 로그인 비밀번호, 액세스 토큰 또는 DB 공개 키를 암호화 키로 재사용하지 않는다. 키를 암호문 옆에 평문 저장하지 않는다.

본문 복호화 키는 잠금 해제 중 메모리에만 두고 장기 저장하지 않는다. 암호화에는 계정·판본·장·버전을 추가 인증 데이터로 결합한다. 자동 잠금, 화면 숨김 시 잠금, 로그아웃 시 메모리 키·표시 본문·오프라인 데이터 제거 경로를 설계한다. 기기 잠금 암호를 잊으면 서가를 초기화하고 온라인 재인증 후 다시 받는 방식으로 시작한다.

이는 잠긴 기기의 저장 파일만 복사했을 때 본문이 그대로 노출되는 위험을 줄이는 방식이다. 잠금 해제된 브라우저, 악성 확장 프로그램, XSS, 기기 관리자, 화면 캡처에 대한 DRM이나 완전한 복제 방지가 아니다. 같은 origin의 다른 앱 코드도 위험 경계에 포함된다. GitHub Pages의 다른 저장소 경로는 서로 다른 origin이 아니므로 `/ministry_report_c/` 경로만으로 IndexedDB를 격리할 수 없다.

**오프라인 중 서버 권한을 실시간으로 확인하는 것은 불가능하다.** 시범에서는 마지막 온라인 관리자 확인 후 저장한 자료를 기기 잠금으로 열도록 한다. 다시 온라인이 되면 서버에서 관리자 자격을 재확인하고, 해제가 확인되면 잠금·로컬 서가 정리를 수행한다. 일시적인 통신 오류와 명시적인 권한 거부는 구분한다. 즉각적인 권한 회수가 필수라면 오프라인 읽기 요구 자체를 바꿔야 한다. 클라이언트 시계에 의존한 임의 만료일을 강력한 권한 통제로 설명하지 않는다.

브라우저의 저장 공간 확보 요청은 시도할 수 있지만 보관을 보장하지 않는다. 사이트 데이터 삭제·브라우저 자동 정리·기기 분실 시 저장분이 사라질 수 있고, 각 기기는 온라인에서 따로 내려받아야 한다. 시범에서는 삭제된 장을 다시 받는 것으로 복구한다.

## 신세계역 이용 조건: 확인 결과와 미확인 항목

2026-10-26 이 환경에서 공식 약관과 온라인 라이브러리로 정상 HTTPS 접근을 시도했으나, 네트워크 프록시에서 403으로 차단되었다. TLS 검증을 끄거나 다른 서비스로 우회하지 않았다.

- 약관 확인 대상: <https://www.jw.org/en/terms-of-use/> (최신 내용·문구 미확인)
- 공식 출판물 확인 대상: <https://wol.jw.org/ko/wol/h/r8/lp-ko> (문서 내용 미확인)
- 현재 신세계역 전체 또는 시범 범위의 서버 저장·온라인 제공·브라우저 오프라인 복제를 허용한다고 판정하지 않았다.
- 무료 다운로드, 개인용 개발, 관리자 한 명에게만 공개한다는 사실만으로 위 이용이 허용된다고 가정하지 않는다. 반대로 조건 원문 없이 일괄 금지라고 단정하지도 않는다.

다음 자료를 대조해야 한다.

1. PDF의 표제지·판권·이용 조건·정확한 판본. “2014년 개정판 / 2026년 인쇄본”은 현재 사용자가 알려준 정보이며 아직 파일로 확인하지 않았다.
2. JW 공식 사이트의 최신 이용 약관. 단순 개인 열람, 본문 추출·재구성, 별도 사이트에서의 제공, 관리자 전용 서버 저장, 오프라인 복제를 각각 검토한다.
3. 관련 출판물의 개별 고지, 저작권 표시와 링크·인용 조건. 설명은 직접 작성하고 최소한의 근거 참조를 우선한다.
4. 조건이 불명확하면 권리자 안내나 확인 가능한 허락을 근거로 결정한다. 관리자 접근 제한·암호화가 이용 허락을 대신하지 않는다.

확인이 끝날 때까지 할 수 있는 작업: 접근 제한 구조, 앱 셸, 본문 자리표시자·성구 참조만 있는 읽기 화면, 자료 구조, 사용자가 제공한 자료의 로컬 추출 품질 검토. 외부에 실제 본문을 게시·수입하거나, 전문 저장이 허용됐다고 안내하는 작업은 보류한다. 조건상 재제공이 어려우면 성구 참조·직접 작성한 사건 설명·공식 본문 링크 방식으로 줄인다. 이 경우 사이트 내부 본문 읽기와 그 본문의 오프라인 읽기는 제공하지 못한다.

## PDF 수령 시 처리

사용자 보유 PDF는 역대기하 15장 일부까지이므로 구약 전체 본문과 열왕기·역대기의 전체 대조, 욥기·예언서 확인을 이 파일 하나로 완료할 수 없다. 사건 통합 요약표는 성구 참조와 검증된 출판물 근거로 먼저 작성할 수 있다. 실제 원문 대조·본문 읽기를 확장할 때는 누락된 책들의 적법하게 이용 가능한 자료가 추가로 필요하다. 파일 수령 전에는 알려진 범위의 완전성도 확정하지 않는다.

필요한 파일은 사용자 보유 PDF 또는 적어도 표제·판권 페이지와 창세기~출애굽기 본문 구간이다. 이 파일은 아직 작업 공간에 제공되지 않았다. 비밀번호나 Supabase 키는 필요하지 않다.

업로드 파일은 Git 추적 대상 밖의 임시 작업 경로에서 조사한다. 원본 해시와 판본을 기록하고 텍스트 추출 후 책·장·절·본문·쪽 대응표를 만든다. 두 단 편집 순서, 머리말/각주 혼입, 줄바꿈·공백, 절번호 누락, 장 경계, 파일과 각 추출 구간의 끝이 절 중간에서 잘리지 않는지 확인한다. 표본을 원본과 대조하고 시범 구간은 장·절 누락과 중복을 전수 검사한다. 이름·문장·절 번호를 생성형 AI로 복원하거나 판본을 섞지 않는다. PDF 추출과 연대 검증은 별도 작업이다. PDF 한 파일만으로 출판물의 연대 해석 근거까지 확보되는 것은 아니다.

## 구현 순서와 완료 기준

| 단계 | 수행 내용 | 완료 기준 |
| --- | --- | --- |
| 1. 자료 확인 | PDF 판본·판권·범위·추출 표본, 공식 이용 조건 확인 | 재제공·오프라인 저장의 가능 범위와 미확인 사항이 문서화됨 |
| 2. 권한과 화면 | 독립 성경 메뉴, 관리자 목록/RLS, 본문 없는 탐색 화면 | 익명·비관리자·위조된 클라이언트 요청은 서버에서 거부. 공개 산출물에 본문이 없음 |
| 3. 시범 자료 | 허용된 본문 구간 수입, 사건 묶음과 근거 검증 | 원문 장·절 일치. 연대와 불확실성마다 확인 가능한 근거. 미검토 항목은 구분됨 |
| 4. 오프라인 | 앱 셸 저장, 암호화 서가, 기기 잠금·정리 | 한 번 저장한 장은 비행기 모드 재실행 후 읽힘. 미저장 장·외부 링크는 안내. 평문 캐시와 저장된 키가 없음 |
| 5. 통합 확인 | PC·태블릿·휴대폰, 계정 전환·로그아웃·관리자 해제·저장 실패·서비스워커 갱신 | 기존 봉사 기록/동기화가 유지되고, 관리자 콘텐츠가 다른 계정이나 정적 배포에 노출되지 않음 |

검증에는 격리된 PostgreSQL의 새 RLS 검사와 모의 인증 브라우저 검사, 운영 환경에서 소유자가 확인할 실제 관리자/비관리자 접근 검사를 구분해서 포함한다. 오프라인 검사는 새로고침·브라우저 재실행·잠금 암호 오류·저장 공간 부족·자료 버전 교체와 잘못된 키/변조 암호문 거부를 포함한다.

이 문서는 초기 설계 기록이다. 현재 구현·적용 상태는 [현재 구현 안내](BIBLE_READING_SETUP.md)를 따른다.
