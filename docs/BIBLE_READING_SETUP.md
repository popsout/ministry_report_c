# 성경 시간순 읽기 — 관리자 활성화와 현재 범위

현재 구현은 **8개 시대 / 35개 통합 사건의 직접 작성한 요약 초안**이다. 열왕기·역대기·사무엘 등의 병행 성구, 당시 나라와 통치자, 관련 예언자와 시가서를 연결한다. 욥기·에스더 등 검토가 필요한 위치는 잠정 배치로 표시하며, 요엘은 부록이 제시하는 820년경(?)을 보존해 분열 왕국에 잠정 연결한다. 구체적 연도나 여호와의 증인 출판물의 연대 검증 완료를 주장하지 않는다.

신세계역 본문은 수록하지 않았다. 공식 약관과 출판물 근거를 검토한 뒤, 허용된 범위의 본문 읽기를 추가해야 한다. 현재 공식 성구 버튼은 JW 온라인 라이브러리의 검색 결과를 연다. 오프라인에서는 저장한 사건 요약과 성구 목록만 읽는다.

## 소유자가 한 번 해야 하는 서버 설정

Codex의 공개 연결 키로 DB 관리 SQL을 실행하거나 관리자 계정을 임의로 선택할 수 없다. 최초 관리자는 소유자가 명시적으로 등록한다. 기존 사용자나 봉사 기록은 바꾸지 않는다.

1. Supabase **Authentication → Users**에서 본인 이메일 계정을 열고 **User UID**를 복사한다. 비밀번호·인증 링크·토큰은 필요 없다.
2. 작업 산출물 **`private-import/bible-setup.sql`**을 연다. `__MY_ADMIN_UUID__` 한 곳을 방금 복사한 UUID로 바꾼다. 따옴표는 유지한다. 파일에는 스키마·관리자 등록·35개 요약을 넣는 SQL이 함께 들어 있다.
3. Supabase **SQL Editor → New query**에 전체 내용을 붙여 넣고 실행한다. 정책을 다시 만드는 구문 때문에 경고가 표시될 수 있다. 기존 봉사 테이블의 데이터 삭제나 변경은 포함하지 않는다.
4. 사이트를 새로고침하고 같은 계정으로 로그인한 뒤 **성경 시간순 읽기** 메뉴를 연다. 다른 계정은 로그인해도 자료를 받을 수 없어야 한다.

설정 파일과 실제 사건 JSON은 `private-import/`에 두고 Git에서 제외한다. 본문·자료를 공개 JS 번들이나 gh-pages에 넣지 않는다. 일반 정책 코드만 `supabase/004_bible_reading.sql`로 관리한다. 작업 환경이 초기화되기 전에 개인 설정 파일을 보관한다. 서비스 키나 비밀번호를 이 파일에 넣을 필요는 없다.

## 화면과 읽는 방법

- 큰 흐름의 시대 카드 → 그 시대의 사건 목록 → 사건 요약.
- 사건별로 나라·왕, 관련 예언자, 병행 성구를 함께 본다. 여러 왕의 시대에 걸친 사건 묶음은 화살표와 주석으로 구분한다.
- 이전/다음 사건으로 시대를 넘어 이동한다. 전체 시대 보기로 돌아갈 수 있다.
- 근거·배치 안내와 검토 상태를 펼쳐 확인한다. 임의로 미상의 파라오 이름이나 재위 연도를 채우지 않는다.
- 실제 읽는 위치의 기기 간 동기화·전문 검색·완성된 장별 성경 읽기는 아직 포함하지 않았다.

## 오프라인 서가

1. 온라인에서 관리자로 자료를 연 다음 **이 기기에 저장**을 누른다.
2. 로그인 비밀번호와 다른 **8자 이상 기기 잠금 암호**를 두 번 입력한다. 추측하기 어려운 긴 암호가 저장 파일 복사 공격에 더 유리하다. 잠금 암호는 서버로 보내지 않으며 저장하지 않는다.
3. 이 기기의 IndexedDB에는 AES-256-GCM 암호문, 임의 salt·IV, PBKDF2-SHA-256 반복 수(310,000), 계정 UUID와 저장 시각만 보관한다. 암호화 AAD에 버전·계정을 결합한다. 현재 전체 요약 목록을 한 문서로 저장한다. 이후 실제 장별 본문은 별도 검토가 필요하다.
4. 공개 앱 화면은 Service Worker가 별도로 저장한다. API·Auth 응답이나 복호화 자료는 Cache API에 넣지 않는다. 저장과 첫 Service Worker 설치가 완료된 다음 오프라인 새로고침을 확인한다.
5. 인터넷이 끊기면 기기 잠금 암호로 **저장된 서가**를 연다. 아직 내려받지 않은 자료와 외부 링크는 사용할 수 없다. 화면을 다른 탭으로 전환하면 서가가 잠긴다.
6. 로그아웃은 오프라인 저장 자료도 제거한다. 암호를 잊으면 온라인에서 관리자로 다시 저장한다. 브라우저의 사이트 데이터 정리나 용량 부족으로 저장분이 사라질 수 있으므로 영구 보관은 보장하지 않는다.

온라인 복귀·화면 복귀 시 관리자 자격을 다시 확인한다. 관리자 해제가 확인되면 이 계정의 서가도 지운다. 오프라인 중의 즉각적인 권한 회수는 불가능하다. 잠금 해제 중인 메모리, 화면 캡처, 악성 확장·XSS·기기 관리자에 대한 완전한 보호/DRM은 아니다. 같은 origin의 다른 GitHub Pages 경로도 보안 경계에 포함된다. 저성능 실기기에서 암호화 속도 확인은 추가로 필요하다.

## 테스트와 적용 범위

- 로컬 PostgreSQL 엔진에서 익명·비관리자 차단, 관리자만 읽기, 자기 권한 부여/본문 변경 금지, 관리자 해제 후 차단을 검사한다. 운영 계정 2개로 검증한 결과와 구분한다.
- 모의 인증 브라우저에서 통치자·병행 성구 표시, 암호화 저장, 잘못된 암호 거부, 오프라인 해제, 로그아웃 정리를 검사한다.
- 실제 production 빌드의 Service Worker로 오프라인 새로고침 후 잠금 해제를 별도 검사한다. 실행: `CHROMIUM_PATH=/usr/bin/chromium npx playwright test --config playwright.offline.config.ts`.
- 실제 운영 서버의 관리자 정책은 위 SQL을 소유자가 실행한 뒤 확인해야 한다. 설정 전에는 새 메뉴가 잠긴 안내 화면으로 열린다.

초기 34개 사건 단계의 구현 검증: 기본·DB 정책 검사 23개, 개발 서버 브라우저 검사 47개, production 오프라인 재시작 검사 1개 통과. 실제 사건 34개의 관리용 수입 SQL도 격리된 PostgreSQL에서 수입·조회 동작을 확인했다. 출판물 내용의 연대 검증 완료나 실제 운영 관리자 등록 완료를 의미하지 않는다.

## 사건별 연대 표시 업데이트

사건 목록과 상세 화면에 연대 표기 및 펼쳐 보는 근거 설명을 추가했다. 연도 단위(`dated`)는 표시의 정밀도이며 사실 검증 완료를 의미하지 않는다. 세기·범위·추정(`approximate`), 상대적 시기만 앎(`relative`), 시대 자체 미상(`unknown`)을 구분한다. 기존 자료에 새 필드가 없으면 **연대 미등록**으로 표시하며, 이를 시대 미상으로 오인하지 않는다. 기존 암호화 서가도 계속 읽을 수 있다.

연대 표시를 처음 추가한 단계에서는 모든 연대가 `reviewed=false`인 참고 초안이었다. 아래 PDF·부록 대조 이후 해당 근거를 확인한 항목만 갱신했다. 당시에는 출판물 원문에 접근하지 못해 특정 출판물의 항목·문단을 대조했다고 주장하지 않았다. 성구는 배경·기간·선후관계 확인의 출발점이며, 성구에 기원전 절대연도가 직접 쓰여 있다는 뜻은 아니다. 예루살렘 멸망의 기원전 607년처럼 일반 역사학의 연대와 다른 값은 근거 설명에서 체계를 구분한다. 창조 전체는 시대 미상으로, 바벨 등 상대적 위치를 알 수 있는 사건은 절대연도 미상으로 표시한다.

- 아직 초기 설정을 하지 않았다면 갱신된 `private-import/bible-setup.sql`을 사용한다.
- 이미 관리자·자료를 등록했다면 `private-import/bible-dates-update.sql` 전체를 SQL Editor에서 실행한다. 관리자 재등록이나 자료 삭제 없이 `005_bible_chronology.sql`의 새 열과 사건별 참고 연대만 추가한다.
- 최신 연대를 오프라인에도 반영하려면 온라인에서 **이 기기에 저장**을 다시 실행한다. 기존 서가를 자동으로 삭제하거나 잠금 암호를 알아내어 갱신하지 않는다.

## 제공 PDF 대조 이후의 변경

PDF 1차 대조 결과는 [당시 보고서](BIBLE_PDF_REVIEW.md)에 기록했다. 이 단계에서 13개 사건에 원문 대조 기록 29건을 붙였으며, 이후 부록·병행 기록 대조로 아래와 같이 갱신했다. 사건 요약 전체의 검토 상태는 여전히 초안이다. `chronology.basis_type=scripture`와 `reviewed=true`는 해당 성구의 재위년·배경을 확인했다는 뜻이며 출판물의 절대연도까지 확인했다는 뜻이 아니다. 미검증 연대는 주 화면에서 보류한다. 정정된 책 이름과 왕명, 원문 근거를 적용하려면 `private-import/bible-verification-update.sql`을 사용한다. 기존 연대 업데이트 파일과 초기 설정 파일도 같은 최신 자료로 갱신했다.

## 마지막 PDF의 부록 대조

현재 자료는 네 파일·1,772 PDF쪽을 기준으로 한 [일람표·부록 대조 결과](BIBLE_APPENDIX_REVIEW.md)를 따른다. 요엘을 추가해35개 사건이며, 출처의 ‘경’·물음표·기록완료/망라기간 구분을 유지한다. `chronology.basis_type=calculation`은 공식 자료의 기준점과 본문 연수를 연결한 계산으로, 출처에 결과가 직접 적혔다는 뜻이 아니다. PDF 쪽수는 파일 안 위치와 전체 합본 기준 위치를 함께 표시한다. ‘여호와의 증인 공식 자료를 기준으로 한 개인 학습 도구’이며 공식 웹사이트가 아님을 화면에 표시한다.

공개 앱 셸의 새 버전은 필요한 파일을 모두 캐시한 다음 활성화하도록 했다. 작성 중인 화면을 강제로 새로고침하지 않으면서, 다음 오프라인 재실행에 오래된 파서가 남는 위험을 줄인다. 저장된 암호문이나 잠금 암호 형식은 바꾸지 않는다.

## 개인 검토 화면

운영 서버에 초기 스키마와 관리자를 등록하기 전에도 이 대화에 첨부한 `private-import/bible-review.html`로 현재35개 사건 화면을 눌러볼 수 있다. 다운로드해 브라우저에서 여는 개인 파일이며 서버 로그인·암호화 서가와는 별개다. 원본 파일은 Git에서 제외한다. 생성: `node scripts/build-reading-review.mjs` (Vite가 설치한 고정 esbuild 도구 및 비공개 사건 JSON 필요). 자세한 대조 내용과 구분은 [병행 기록 추가 대조](BIBLE_PARALLEL_REVIEW.md)를 따른다.

운영 사이트에서 준비 중이라면 기존 계정으로 로그인한 후 표시되는 **본인 UID 복사**를 사용한다. 채팅에 비밀번호나 토큰을 보낼 필요 없이 소유자가 초기 설정 SQL의 UID를 바꾸어 Supabase SQL Editor에서 실행한다. 이미 등록한 경우 최신 정정 파일은 관리자 등록을 바꾸지 않고 자료만 갱신한다.

이번 추가 대조 후 자료는35개 사건·8개 시대·원문 근거77건이다. 근거 수는 사건 전체의 검증 완료 수가 아니다. 운영 사이트와 동일한 표시 코드의 개인 미리보기에서 PC·모바일 탐색을 확인했다.
