# 차곡 · 나의 봉사 기록

현재 목표는 **로그인 없이 한 기기에서 쓰는 봉사 기록장**입니다. UI와 실제 사용 흐름을 먼저 완성하고, 여러 기기 동기화와 백업은 후속 단계로 진행합니다. Google/Supabase 설정은 지금 필요하지 않습니다. 기존 온라인 연동 파일은 향후 작업 참고용으로 남겨 두었으며, 현재 앱은 이를 불러오거나 외부 서버에 접속하지 않습니다.

## 현재 기능

- 날짜별 호별 / 편지 / 전시대 봉사 기록 추가·수정·삭제와 메모
- 시간 선택: 1~8시간 + 0/15/30/45분. ‘시간 없음’으로 15분만 기록 가능
- 캘린더의 날짜별 시간 합계
- 연도·월별 일반 / 보조 파이오니아 / 정규 파이오니아 설정 및 테마
- 이번 달 합계, 봉사한 날, 기록 횟수 (기록 1건 = 1회)
- 이번 달/전체의 **시간 기준** 도넛 비율, 각 형태의 시간과 횟수
- 브라우저 저장, 새로고침 후 복원, 같은 브라우저 탭 변경 반영
- 저장 실패 시 입력 보존, 손상된 데이터 자동 덮어쓰기 방지
- 실제 기록과 분리된 예시 화면 (`?preview=1`), PC/태블릿/휴대폰 배치

## 직접 열어보기

### 단일 HTML 파일 (PC에서 빠르게 확인)

작업 결과 `release/chagok.html`을 PC로 다운로드하고 Chrome/Edge 등에서 여세요. 앱 화면과 코드가 한 파일에 들어 있어 별도 설치·로그인이 필요하지 않습니다. 폴더의 원본 `index.html`이 아니라 **release/chagok.html**을 열어야 합니다.

파일 주소에서의 저장 동작은 브라우저에 따라 다를 수 있습니다. 이 클라우드의 Chromium은 관리자 정책으로 file:// 접근이 차단되어, 파일을 직접 여는 동작은 검증하지 못했습니다. 단일 HTML 자체의 화면과 저장 동작은 HTTP로 제공하는 조건에서 검증합니다. 다른 브라우저·다른 파일 위치·다른 웹 주소의 기록은 별도로 취급될 수 있으므로, 지속 사용을 시작할 때는 실행 주소/파일 위치와 브라우저를 고정하세요.

ChatGPT 웹의 이 클라우드 설정 화면은 웹사이트 실시간 미리보기를 지원하지 않습니다. 클라우드 환경 게시가 앱의 웹 배포를 의미하지도 않습니다. 휴대폰에서도 같은 주소로 열려면 추후 정적 웹 호스팅이 필요하며, Google 로그인 설정과는 별개의 작업입니다.

### 개발 서버

Node.js 22 이상 (검증 버전: 24).

```sh
cd /workspace/ministry_report_c
npm ci
npm run dev -- --port 5173 --strictPort
```

본인 PC에 코드를 내려받아 실행할 경우 브라우저에서 개발 서버 주소를 여세요. 환경 변수가 설정되어 있어도 현재 앱은 로그인 없이 로컬 저장으로 실행됩니다.

```sh
npm run build
npm run build:standalone
npm test
CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
```

다른 PC에서는 `npx playwright install chromium`을 실행한 후 `CHROMIUM_PATH` 없이 `npm run test:e2e`를 실행합니다. 브라우저 테스트는 별도의 5174 포트를 사용합니다.

## 저장 위치

현재 기록은 **현재 기기의 현재 브라우저**의 localStorage에만 저장됩니다. 브라우저 데이터 삭제·시크릿 모드 종료 등으로 기록이 사라질 수 있습니다. 서버 저장, 자동 동기화, 백업 내보내기/복원은 아직 구현하지 않았습니다. 예시 화면의 기록은 연습용이며 새로고침하면 초기화되고 실제 기록에는 저장되지 않습니다.

기록과 월별 신분 설정은 버전이 있는 별도 저장 모듈(`src/lib/localJournal.ts`)을 통해 저장합니다. 이후 온라인 연동·데이터 이전은 이 저장 계층을 확장하는 방향으로 진행합니다.

## GitHub Pages 배포

`.github/workflows/pages.yml`은 main 브랜치에 코드를 올리면 테스트·빌드 후 정적 앱을 배포합니다. Vite의 상대 자산 경로를 사용해 저장소 하위 주소에서도 실행됩니다. 배포에 Supabase/Google 키나 환경 변수는 필요하지 않습니다. 개인 기록은 서버나 GitHub에 전송되지 않고 방문한 브라우저에만 저장됩니다.

저장소 소유자가 최초 1회 GitHub **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 설정해야 합니다. Pages 사용 가능 여부는 저장소 공개 여부와 GitHub 요금제에 따라 다릅니다. 배포를 위해 저장소 공개 범위를 자동 변경하지 않습니다.

설정 후 **Actions → Publish journal to GitHub Pages → Run workflow**를 실행하거나 main에 새 커밋을 올리세요. 성공한 실행의 **github-pages** 환경에서 실제 배포 주소를 확인합니다. 설정 전이거나 실행 실패 상태라면 배포가 완료된 것이 아닙니다.
